# Rental Lagbe

Next.js 16 App Router + React 19. `README.md` only names the project, so treat this file as the onboarding note.

## Commands

- Scripts are only `npm run dev`, `npm run build`, `npm start`, `npm run lint`. There is no test runner or `typecheck` script; use `npx tsc --noEmit` for a type check.
- `npm run lint` uses flat config `eslint.config.mjs` (`eslint-config-next` core-web-vitals + typescript); `.next/`, `out/`, `build/` and `next-env.d.ts` are ignored.
- Do not hand-edit `next-env.d.ts` — it is gitignored and regenerated by Next.

## Toolchain / UI quirks

- `next.config.ts` enables `reactCompiler` and a **Turbopack CSS rule** loading `@tailwindcss/turbopack`; keep it. Tailwind 4 is configured entirely in `src/app/globals.css` — there is no `tailwind.config.*` (`components.json` sets `tailwind.config: ""`).
- shadcn `base-nova` style with `@base-ui/react`; generated components go in `src/components/ui/` using `components.json` aliases (`@/*` → `src/*`).
- `src/lib/utils.ts` just re-exports `cn` from the `cn` package — there is no local clsx/tailwind-merge helper to extend.

## Environment

- `.env` is gitignored and there is no `.env.example`. Names referenced in code: `MONGO_DB_CLIENT_STRING`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `BETTER_AUTH_URL`, `NEXT_PUBLIC_API_BASE_URL`.
- `src/lib/auth.ts` constructs the `MongoClient` at module scope, so missing/invalid DB or Google credentials fail during import/boot, not on first request — check env before debugging auth code.

## Architecture / boundaries

- Auth is Better Auth + `@better-auth/mongo-adapter` (database `Rental-Lagbe`): server config `src/lib/auth.ts`, catch-all handler `src/app/api/auth/[...all]/route.ts`, server session helper `src/lib/core/session-server.ts` (`headers()`-based).
- `src/lib/auth-client.ts` exports two clients: `authClient` uses `BETTER_AUTH_URL`, while the named `signIn`/`signUp`/`useSession`/`signOut` come from a second client with no base URL. Most components use `authClient`; prefer it for new code.
- User `role` (`src/types/UserRole.ts`: `customer | owner | admin`) is a Better Auth additional field with `input: false` and default `"customer"` — signup cannot set it; role changes need an out-of-band/admin update.
- Dashboard navigation is role-gated only in the client sidebar (`src/components/dashboard-sidebar.tsx`) mapping to `src/app/dashboard/{customer,owner,admin,...}`; there is no server-side route guard in `src/app/dashboard/layout.tsx`.
- Equipment/user data comes from an **external API** at `NEXT_PUBLIC_API_BASE_URL` via wrappers in `src/lib/actions/` and `src/lib/api/` (e.g. `/owner/add-equipment`, `/owner/equipment/:id`, `/users/:id`, `/equipment/:id` via `getEquipment`). MongoDB here backs auth only — don't hunt for local equipment route handlers.
- `getEquipment()` returns untyped `res.json()`; `src/app/equipment/[Id]/page.tsx` only normalizes/casts it to `EquipmentRecord` and delegates display to `src/components/equipment/equipment-details.tsx`. The image field may be a string or an object (`url` / `data.url`) — `resolveImageUrl()` there handles both, and `next/image` uses `unoptimized` because remote hosts are unrestricted.
- Booking UI is intentionally inert: `src/components/equipment/booking-dialog.tsx` only opens/closes the modal. `Confirm Booking` does **not** calculate totals, check availability, call an API, or redirect to payment — that is planned future functionality, not a bug.
- Slug-to-label maps (`construction-equipment`, `brand-new`, `week`/`weekly`, etc.) are intentionally local to `src/components/equipment/equipment-details.tsx` and `src/app/dashboard/owner/equipment/page.tsx`; the duplication is accepted — don't extract a shared formatter unless asked.
